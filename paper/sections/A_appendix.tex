\section{Protocol, locks and audit}
\label{app:protocol}
\paragraph{Preregistration and locks.} Sample size, tests, model identities, prompts, code and configuration were frozen before the formal run: the run refused to start unless every locked file hash matched (167 files, six prompt hashes, method versions, model and provider identities, seed commitments and the run environment). The analysis code was locked while campaigns ran and before any formal score existed, and was not changed afterwards; the E3 Reader prompt and the remaining Phase~6 code were locked in the same way before any formal score was read. The test-site master seed and the E3 sample seed were committed with salted hashes in advance. The lock did not include the preregistration documents themselves; their hashes at the lock commit, which was pushed before the run, were recorded afterwards.

\paragraph{Execution.} The run used two rented 128-core servers. A development evaluation repeated on the first server was bit-identical to the pilot desktop's, and evaluations and E3 packets repeated on the second server were bit-identical to the first's. The USD~30 API cap was enforced by provider-side limits summing to it, with pacing reserves in the runner.

\paragraph{Budget and locks.} The formal run used \res{campaigns} campaigns and \res{evaluations} evaluations. A development evaluation repeated on the first server was \res{parity.identical} to the earlier desktop run. API spend was USD \res{spend.original} in the first part (USD \res{spend.campaigns} for campaigns) and USD \res{spend.repair} in the second, USD \res{spend.total} in total, under a USD~30 cap. Locks: v1 before the run (code, configuration, prompts, model identities, seed commitments and environment), v2 the E1/E2 analysis code and v3 the Phase~6 code, both before any formal score existed, v4 the hashes of the preregistration documents at the v1 commit, and v6--v8 for the second part (v5 was superseded before use); every v6--v8 lock requires the rendered prompts to equal v1's and records the files changed since v1.

\paragraph{Integrity.} Every planned campaign and evaluation completed, so no data are missing; \res{repair.failed} attempts in the second part that stopped on dropped provider connections were rerun from the same point and are kept; one branch needed more than the preregistered two retries because of a defect in the model client, handled by a recorded decision (Appendix~\ref{app:original}). An audit confirmed one record per planned identity, that all \res{calls.total} model calls (\res{calls.repair} of them in the second part) were served by the planned model and provider with the planned settings, and that the booked spend equals the spend recomputed from per-call records.

\section{The original run and the correction}
\label{app:original}
\paragraph{The error.} The agent sessions receive the task description with keys in sorted order (canonical JSON), whereas the process predictor and the baseline's Gaussian-process kernel had been trained in the contract's field order, and the deployed code took policy fields in the order received. Validation had exercised only the offline path. On development data the misordering roughly doubled the predictor's error at day 90 (5.8 to 12.6~\eur{}) and lowered the kernel's cross-season ranking accuracy from 0.81 to 0.69 (decision record 2026-10-05). It affected only the predictor tool and the baseline: language-model Endpoint branches, pre-experiment recommendations and the shared day-0 designs never used them, and a scan of all \res{repair.audits} language-model audits found \res{repair.branches} Full branches that had received a predictor output (DeepSeek \res{repair.branches.deepseek}, GLM \res{repair.branches.glm}, MiMo \res{repair.branches.mimo}).

\paragraph{The correction.} The fix maps fields by name into the training order and adds a test comparing the deployed and offline paths. Under a new lock (prompts identical to lock v1): (i) the baseline's radius was re-selected on the same development sites by the same rule; (ii) all \res{repair.baseline} baseline campaigns were rerun with the same sites, years and seeds; (iii) each affected Full branch was replayed from its recorded conversation, with every outgoing message checked byte for byte against the original audit (\res{repair.replayed} calls), and continued live from the first predictor output (\res{repair.live} calls); \res{repair.failed} attempts that stopped on dropped connections were rerun from the same point and kept: four branches failed because the model client did not retry connections dropped after a request was sent (a defect that had not occurred in the first part); two completed on their first retry, and the other two failed again (one of them twice) before the client was fixed under a new lock with a recorded decision, after which each completed on its first retry; (iv) the \res{repair.evaluations} changed recommendations were evaluated, the \res{repair.e3packets} E3 packets whose source records changed were rebuilt and re-read, and the boundary sensitivity was repeated for changed recommendations; everything else was reused unchanged; (v) the locked analysis code was run once on the corrected data. The second part cost USD \res{spend.repair}. One host processor socket ran about 35 times slower than the other; jobs were then pinned to the fast socket, and evaluations repeated across sockets were \res{repair.socketparity}.

\paragraph{Original versus corrected results.} Table~\ref{tab:original} lists every primary and secondary test. The language models' own results barely changed; the baseline became stronger (Full mean \res{orig.mean.baseline.full} to \res{mean.baseline.full}~\eur{}), so all three E1 differences became significant, MiMo's gain over its pre-experiment recommendation lost significance, and the E3 Reader-swap losses of the original run, which were significant for all three models and largest on the baseline's packets, disappeared. Both analyses were computed on the same host: the Phase~6 analysis of the original data had first been computed on a different platform, where BCa bounds of samples with many ties differed (largest difference 0.46~\eur{} in one bound), without changing any test decision.

\section{Baseline redesign}
\label{app:baseline}
The preregistered plan first named a plain asynchronous GP/BO as the only numerical comparator. In the eight-site pilot it scored \res{pilot.bo.vsfixed}~\eur{} relative to the fixed reference, which uses no experiments at all, and its two repeats on the same site differed with an SD of \res{pilot.bo.repeatsd}~\eur{} (language models: \res{pilot.llm.repeatsd.lo}--\res{pilot.llm.repeatsd.hi}). A comparator below the zero-experiment reference is not a meaningful baseline, so it was replaced before any test-site campaign was run; the decision referred only to the fixed reference. Its pilot and development results are reported here and it was not run on test sites.

The replacement differs in three ways, all set on development sites only. (i) It starts from the fixed reference and explores within a trust region around the best tried policy. (ii) Its Gaussian-process hyperparameters are frozen from development data (\res{kernel.groups} site-years, \res{kernel.crops} crops with random policies) instead of being refitted from two to six crops in each campaign. A kernel that separates a season effect common to all policies from the policy effect was chosen over a product kernel by a rule fixed before the fit: it ranked second-season crops from first-season data with accuracy \res{kernel.cross.interaction} against \res{kernel.cross.product}, and its held-out error on campaign-sized data was \res{kernel.rmse.interaction}~\eur{} against \res{kernel.rmse.refit} for per-campaign refitting and \res{kernel.rmse.mean} for the mean of the observed crops. (iii) Only tried policies are recommended. The initial trust-region radius was chosen among 15, 25 and 35\% of each range by mean development score (\res{radius.15.mean}, \res{radius.25.mean} and \res{radius.35.mean}~\eur{}; fixed reference \res{radius.fixed}; plain BO \res{radius.v3.mean}); the selected \res{radius.selected}\% is the largest candidate, and the frozen rule allowed no further candidates. These are the scores of the corrected agent; with the field-order error (Appendix~\ref{app:original}) the same rule had selected \res{orig.radius.selected}\% (\res{orig.radius.15.mean}, \res{orig.radius.25.mean} and \res{orig.radius.35.mean}~\eur{}). On the pilot sites its repeat SD was \res{pilot.baseline.repeatsd}~\eur{}.

\section{External validity check}
\label{app:external}
Before the study we tested whether GreenLight reproduces observed climate when driven by the actions of the 2019 Autonomous Greenhouse Challenge teams, in a one-shot temporal holdout with thresholds fixed in advance. It failed: pooled RMSE was \res{agc.temp.rmse}\,$^\circ$C for air temperature (threshold \res{agc.temp.limit}) and \res{agc.rh.rmse} percentage points for humidity (threshold \res{agc.rh.limit}); CO$_2$ passed (\res{agc.co2.rmse}~ppm, threshold \res{agc.co2.limit}). SlowLab is therefore a simulated benchmark; its numbers are not predictions for a real greenhouse.

\section{Agent interface details}
\label{app:interface}
\paragraph{Messages.} The system message states the role (``You run a greenhouse experimentation campaign as the experimenter. Plan experiments, read the evidence your feedback condition allows, and recommend one management policy at the final day.''), then the public task description, the tool catalogue and the reply format, all as canonical JSON. Every later call ends with one user message holding the state digest, the latest result and the instruction. The reply format asks for exactly one JSON object: either \texttt{\{"type": "campaign", "action": \{...\}, "reason": "..."\}} for one of the five actions, or \texttt{\{"type": "tool", "name": "...", "args": \{...\}\}} for one analysis tool; any reply may carry \texttt{"notes"} to replace the notebook. The pre-experiment recommendation uses a separate grower prompt with the task only. The full prompts are hashed in the lock and released with the code.
\paragraph{Tools.} \texttt{runs} (every crop started, with released totals and margins); \texttt{series\_summary} (daily count, mean, minimum and maximum of a channel already read); \texttt{fit\_outcome\_model} (a Gaussian process of crop margin on policy and planting date, fitted to completed crops); \texttt{predict} (margins of up to 32 policies from that fit); \texttt{predict\_crop\_outcome} (the process predictor: final harvest, resources and margin of a running crop from its readings so far); \texttt{space\_filling\_candidates} (up to 64 feasible policies spread over the allowed ranges). Tools analyse only data the agent has already received; they do not advance time.
\paragraph{Context.} At most 80{,}000 characters per prompt and $5\times10^6$ per campaign; the six most recent results are shown in full and older ones as one-line stubs; reasons are truncated to 400 characters; at most 200 model calls. When the remaining characters fall below one prompt plus a reserve, or the call budget is nearly spent, the harness advances to day 365 and accepts only a recommendation.

\section{Environment card and broader impact}
\label{app:card}
\paragraph{Environment card.} \emph{Purpose:} evaluating how agents plan, monitor and read slow, irreversible experiments in a shared facility. \emph{Composition:} a site distribution (cultivar, facility, price and per-compartment parameters), audited Cabauw weather years (KNMI, \ccby{}), the GreenLight model at a pinned commit, the task contract, the agent interface and tools, and a private evaluator. \emph{Splits:} development sites and years for tuning, eight pilot sites for power, \res{sites} test sites drawn from a committed master seed that stays sealed. \emph{Released records:} public campaign transcripts, model calls and replies with hashes, evaluation records and history packets (\ccby{}); private site parameters, seeds and simulation traces are not released. \emph{Known limitations:} not calibrated to a real greenhouse (Appendix~\ref{app:external}); declared assumptions are marked in Table~\ref{tab:task}. \emph{Maintenance:} the code repository records every change, and every frozen record is hash-locked.
\paragraph{Broader impact.} SlowLab measures agents in a simulator; it involves no human subjects or personal data, and its results are not advice for real greenhouse operation. A benchmark of autonomous experimentation could encourage deploying agents in real facilities before they are reliable; our results argue for caution, since the tested agents left most of the available improvement unused and did not act on in-season information. Sealing the test seeds keeps the test sites useful for future agents.
