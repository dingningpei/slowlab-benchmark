# V2.2 Phase 0：模型兼容性检查

日期：2026-09-27。状态：**遇到兼容性问题暂停；Phase 0 尚未完成**。

本次仅检查新实验设计能否落实为一致的任务合同。未冻结任务合同，未运行 LLM API，未下载数据，未启动正式实验。历史数据审计的完成状态不等于本阶段完成。

## 发现的问题

当前代码中，作物生长、气候执行与根区响应还不是一个经过检查的统一闭环。不能直接把这些组件及公开数据拼接后，声称它们共同描述了同一种温室作物。

| 组件或数据 | 本地证据 | 对任务合同的影响 |
| --- | --- | --- |
| 当前主环境 | `slowlab/env.py` 实例化 `ManagedTomgro` 并调用其状态推进；`slowlab/world.py` 使用 `TomgroModel` | 当前主环境没有接入 GreenLight 的执行器—气候闭环或根区响应 |
| 作物驱动 | `slowlab/tomgro.py` 使用温度、CO₂、光照等驱动；含文献参数与近似子函数 | 不能将管理目标直接作为实际气候的路径当成已实现的物理执行器模型 |
| 根区水盐平衡 | `slowlab/root_zone.py` 明确独立于作物胁迫/产量响应 | 水盐守恒成立并不证明灌溉或 EC 会正确影响产量 |
| EC 响应 | `slowlab/root_zone_response.py` 明确为文献曲线检查，尚非环境响应 | 不能仅凭 EC 数据或静态经验曲线开放 EC 优化 |
| GreenLight 接口 | `slowlab/greenlight_adapter.py` 提供输入、单位、物理检查及蒸腾水需求转换；`slowlab/greenlight_sequence.py` 处理输入序列 | 这些接口不足以证明作物—气候—根区已完成双向耦合；不是断言 GreenLight 本身没有作物模型 |
| AGC 2023/2024 | `docs/agc2023_development_audit.md`、`docs/agc2024_input_feasibility.md`：矮生番茄，高密度盆栽；2024 公开包缺少配套参数化作物模型 | 不能直接校准当前 TOMGRO 作物族的生物量、密度和收获规则 |
| 设施模板 | `configs/agc2019_facility_evidence_v0.json` 仍有面积口径和灯具热分配问题；`slowlab/facility.py` 的既有面积属于 benchmark 设定 | 不能把既有默认参数写成已验证的真实设施 |

因此，冻结作物/设施之前，尚不能诚实确定完整的 treatment schema、收获收益、周期、停止与重种的物理含义。问题是**当前组件的兼容性与集成证据不足**，不是所有公开数据都不能用，也不是必须先开展实体温室实验。

```sh
PYTHONDONTWRITEBYTECODE=1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -m pytest -q -p no:cacheprovider tests/test_root_zone.py tests/test_root_zone_response.py
```

结果：12 passed，0.12 秒。这只验证现有独立模块的测试断言，不证明动态产量耦合、作物兼容性或真实轨迹一致性。本次没有读取新盲测输出或重新拟合历史失败的模型。

## 建议的解决路径（待下一次继续）

1. 优先核查一个内部一致的 GreenLight 原生气候—作物模型族，确认其状态、作物参数、执行器输入、产量和收获定义。只做代码/参数审计及必要的小型烟测，不先拼接不同作物模型。
2. 选择与该模型相容的一种作物及设施模板，逐字段区分文献依据、实测依据和模拟假设。AGC 矮生番茄数据可按适用范围支持输入/设施证据，不能跨作物移植产量校准。
3. 第一版建议根区固定为充分供水供肥背景，暂不开放 EC/灌溉优化；必须声明这缩小了自动化实验的范围。若要纳入，先补齐水分/盐分→作物生长与产量的动态耦合及验证。
4. 通过兼容性检查后，再完成 Phase 0 的管理方案 schema、周期/预算、收益和停止/重种规则；实现工作属于后续 Phase 1。

下一次解除本暂停所需证据：选定模型族的作物与设施参数映射、控制量到实际气候再到作物/产量的明确计算路径、支持与不支持变量清单。这里只要求模型结构一致和假设可审计；不把它改称为通过真实温室轨迹验证。
