# V2.2 Phase 1：逐步执行链审计范围

日期：2026-09-28。当前四隔间全年 pilot 是固定策略的**运行时间／生命周期**检查。脚本每个 300 秒步会断言：四间先共同读取已到达控制器测量，随后收齐 requested commands；充足中央供给合同下 realised commands 与 requested 完全相同；四间物理步进都结束后才发布新端点；资源账按连续时段积分。它只持久化逐日汇总、生命周期事件和末状态，**没有逐步可独立复查的事件链**。因此全年 pilot 即使通过，也不能单独验收正式 executor 的完整活动日志、代理隔离或中途改变下一实验。

短窗脚本 `scripts/check_v22_four_unit_runtime_window.py` 新增可选 `--trace-gz`。开启时将每步四间的控制器记录及测量/到达时刻、requested/realised、物理步进后的资源增量、公开端点记录和输入行数写入私有 gzip JSONL。`scripts/audit_v22_tick_trace.py` 独立检查时间因果、指令实现在本合同下完全相同、观测在端点发布、资源增量与最终账一致，并保存原始文件哈希。合成破坏测试覆盖未来测量、实际指令被改动和公开观测缺失。该审计不能证明 GreenLight 方程准确，也不能从记录反演隐藏状态。

**下一门槛：**等全年 pilot 结束，避免东京单物理核心同时跑两个负载；再运行一日四隔间带 trace 的动态短测并审计。通过后将同一事件格式接入正式活动调度，覆盖停种、清理、重种、根据已产生观测改变下一实验，以及失败时保留完整记录。原始 trace 属于私有执行日志，不能进入 LLM 提示；正式实验前须定义可公开的脱敏摘要。

## 2026-09-29 进度勘误

上述下一门槛写于固定策略全年 pilot 尚未完成时；该 pilot 现已通过独立结构审计。`scripts/check_v22_campaign_annual_dynamic.py` 现将同格式私有轨迹接入四隔间 `CampaignExecutor`，每天回写进度与 RSS，上限内执行预先脚本化的第 14 天观测、依据已到达室温选择**下一轮**策略、提前停种、清理重种、错峰实验和第 365 天结算。`scripts/audit_v22_campaign_annual_dynamic.py` 流式重读每个 tick，核对哈希、时间因果、请求/实现、资源增量、逐日进度和结算。当前只是**已实现并排队**，未取得全年结果。

一次和深土壤全年情景并发的一天动态短测达到 180 秒外层时限，无法据此判断物理模型；东京服务器只有一个物理核心。已安排顺序作业：先完成 8°C/20°C 两个全年土壤情景并核对状态，再单独跑一天动态短测，通过后才跑全年动态活动。原始私有 trace 留在服务器，不进入 Git 或代理提示。任何失败需保留原身份和已产生进度，不能把未完成作业算成通过。
