# Phase 1：停止/清理期的无作物模式问题

日期：2026-09-27。状态：**显式空温室模式短测通过；待机控制合同缺口待解决，Phase 1 未完成。**

## 检查范围

为接入合同要求的停止、清理、空置和重种流程，本轮首先检查清空作物后能否继续推进温室物理状态。没有为了完成调度代码而假装清理期模型已经可用，也没有运行长周期模拟。

## 已确认的问题

锁定模型中的方程为：

- `lai = sla * cLeaf`；
- `capCan = capLeaf * lai`；
- `d(tCan)/dt = (1/capCan) * (...)`。

将作物清空为 `cLeaf=0` 后，LAI 与冠层热容量均为零，逆热容量无定义。这个结果由 `scripts/v22/audit_empty_crop.py` 校验四个源文件哈希后，按原方程完成代数复现，记录在 `results/v22/phase1_empty_crop_audit.json`。没有启动求解器，也不把代数检查描述成动态仿真失败。

所以现有活作物模型不能通过“清空几项状态后原样运行”实现空置。若保留原作物直到重种，清理期仍有生长、蒸腾、CO₂ 交换及可能的收获，不符合已冻结合同；如果重置整个温室，又会抹去管道、空气等真实连续状态与资源消耗。

## 已做的保护

`ReusableGreenLight.step` 在进入求解器之前检查冠层叶质量必须为正且有限，否则明确报告 crop-absent mode 尚未实现。此保护仅阻止错误使用，不冒称实现了空温室。

48 项相关轻量测试通过，新增零/负/非有限冠层阻断及正常冠层继续支持的检查。此前六步复用等价性结论仍适用于正冠层、活作物模式。没有把 NaN 转零、clip 或微小虚拟 LAI 作为解决办法。

## 建议的实现路径

实现明确的 **active / empty** 模式，而不是仅改状态值：

1. empty 模式保持空气、湿度、CO₂、围护、土壤和设备等设施状态连续；作物碳库与生长/呼吸/收获流关闭，作物蒸腾、吸收与冠层交换关闭。
2. 显式替换无作物时的冠层温度方程，避免求值 `1/0`。不能只乘一个零开关，因为求值器仍可能计算无效分支；检查所有依赖项的零冠层极限。
3. 停止时将被移除的作物状态记入终止日志，不把未收获碳库计作已实现收入。清理与空置期间继续推进设施并累计实际待机资源。
4. 重种只初始化新作物相关状态；按照合同将新冠层温度及温度平均状态初始化为当时室温。保持其余设施状态，不重置日历或历史账本。
5. 优先各解析一次 active/empty 模型或采用经验证的安全分支，避免重新引入每 5 分钟加载模型的性能问题。
6. 验证：active→empty→active 的状态映射、零作物流量、有限导数、边界资源账、清理占用及延迟重种限制。先短时单隔间通过，再接多隔间调度。

下一步不需要更换数据集、放弃 GreenLight 或改变 96 m² 目标。它是执行生命周期所需的模型模式切换工作。按用户要求，本轮确认问题并加入保护后暂停，未声称 Phase 1 或整个生命周期完成。


## 实现更新：显式 active / empty 模式

`ReusableGreenLight` 支持两种分别编译并缓存的模式；`CropLifecycle` 提供停止和重种状态映射。停止移除四个碳库、清零作物积温，记录丢弃作物且收入为零；所有非作物状态及绝对时钟连续。重种只恢复原生作物初值，冠层温度和日均冠层温度取当前室温，清理未满两天则拒绝重种。

空模式显式关闭作物碳交换、生长、呼吸和收获，并冻结无物理意义的作物温度状态。LAI=0 的原生辐射透过关系保留。禁用的生长管冠层交换也显式关闭。实际求解发现 `gamma` 补偿点通过 `j25CanMax` 再次除以 LAI，导致辅助输出 gamma/p/r 非有限；现在空模式关闭这三个计算。gamma 的零值是未启用的占位符，不是生理参数估计。

验证记录：`results/v22/phase1_empty_mode_result.json`。单线程实模型测试约 8 秒，运行 300 秒活作物、600 秒空温室。所有输出有限；碳通量与蒸腾为零，冠层辐射残差最大 4.996e-15，验收绝对容差 1e-10。固定测试指令 uBoil=0.4 产生 48 W/m² 送达热量，证明空温室仍消耗资源，**这不是正式待机策略或已经完成的资源账本**。50 项轻量测试通过。

重种边界目前通过合成状态单元测试验证，未运行完整两天空置再重种的动态验证；未接入多隔间调度、权限层和成本积分。不得将短测描述成完整生命周期验收。

## 当前暂停点：待机控制缺少合同定义

机器合同要求停止立即结束处理、清理两天、待机能耗计入活动层，但未定义清理/空置时的加热、通风、补光、CO₂ 指令。继续沿用上一个作物处理与“结束处理”冲突；全部关闭或维持最低温度也会改变能耗和重种初始状态。不能把测试命令悄悄用于正式调度。

建议下一步明确一个全方法共用、代理不可修改的设施待机控制器：关闭补光与 CO₂，按最低保护温度供暖，并设过热通风规则；阈值作为开发假设写入新版合同并做敏感性检查，不冒充真实设施运行规程。定义后接资源积分和完整清理—重种动态验收。按照“遇到问题停下来”的要求，本轮停在这个合同缺口，不宣布 Phase 1 完成。
