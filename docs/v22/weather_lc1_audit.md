# Phase 1：Cabauw lc1 补缺产品本体审计

日期：2026-09-27。用户批准的 2017–2020 气象和辐射产品、2016-12 边界月已按两阶段获取，共 98 文件、18,413,090 字节；逐文件大小和 SHA-256 在 Git 外缓存清单中核对。样本门槛见 `results/v22/weather_gapfilled_sample_audit.json`，完整逐月数据见 `results/v22/weather_gapfilled_quality_audit.json`。这一步只验证外部天气强迫的候选数据质量，不是 GreenLight 动态轨迹验证，也不是温室实测验证。

## 连续性和来源

两套文件的 `time_bnds` 在同月完全对齐，每行代表一个 10 分钟区间；2017–2020 共 210,384 个区间。TA002、RH002、TD002、F010、SWD、LWD 联合缺测均为零，2016-12 两份边界文件相同通道也无缺测。气象产品和辐射产品的 SWD 在四年逐行完全相同，可选辐射产品为唯一短波来源。原始 lb1 对应四年的联合缺测分别为 6.33%、3.81%、2.31%、2.51%，不能把 lc1 的连续性描述为原始连续实测。

|---|---:|---:|---:|---:|
| 2017 | 52,560 | 0 | 3,327 | 2,976 |
| 2018 | 52,560 | 0 | 2,003 | 768 |

所有 lb1 必需通道中标记缺失的时段，在 lc1 相应通道都有数值。lc1 也会合并或推导已有数值，如 RH002 与原始有效值不总相同。其来源索引可逐通道保存：四年合计向下长波索引 2 为 204,832 条，索引 1 为 5,172 条，索引 5 为 82 条，索引 7 为 298 条。不能把 5,552 条“非索引 2”全叫作模型插值。[CESAR 衍生产品的来源标志说明](https://icdc.cen.uni-hamburg.de/thredds/dodsC/ftpthredds/samd/data/mets/00/any/l1/sups/ces/2008/sups_ces_mets00_l1_any_v00_20080601000000.nc.html)给出的对应关系是 1=BSRN、2=Cabauw in-situ、3=Cabauw AWS、5=interpolated、6=Cabauw model、7=De Bilt model；这来自衍生产品，KNMI 当前文件没有内嵌语义表，论文引用时须注明该映射为关联证据而非源文件自身定义。

## 单位和物理值异常

所有 lc1 月文件的 TA002/TD002 单位标签均写为 `degC`，但 TA002 数值跨年约 265–310，符合 K 量级；2017-01 的 TA002 与 lb1 在原始有效处完全相同，而 lb1 明确标 K。**数据集专用解析器须以显式版本规则把 TA002/TD002 按 K→°C 变换，且对值域和 lb1 锚点做失败即停的检查；绝不能通用地相信 lc1 标签或按数值临时猜单位。** RH002 标签 `1e-2`，实际数值为百分比量级；它在 lc1 中从合并温度/比湿推导，作为 QA 通道而不用于主水汽压换算。主水汽压拟由 TD002 的饱和水汽压公式计算，公式和精度需固定。

四年每年有 1,776–3,231 条 RH002 >100% 的 lc1 时段，暂不静默裁剪。夜间 SWD 含小负值，最低约 −5.12 W/m²，四年各约 25,000 条；若 GreenLight 接口要求非负太阳短波，应在转换层显式使用 `max(0, SWD)` 并记账。该修正的负向辐照积分约为年度正向积分的 0.54%–0.80%，应做敏感性检查。LWD 没有负值，天空温度仍需按 GreenLight 的 emissivity 约定转换。

## 使用边界与下一步

这些是同站点真实室外观测与来源替代/填补的序列，可作为候选外部天气强迫；它们不是室内温室轨迹，不校准执行器，也不保证 LLM 未见过原始公开天气。必须把完整天气只交给私有 executor；代理只能按观察事件读取已到达的室内传感器。源文件的十分钟区间平均值不可在区间开始作为已知实时观测发布。

下一步建立固定版本的天气解析器和严格测试：逐文件哈希、UTC 区间、K 数值锚点、来源索引、短波裁剪日志、露点水汽压和长波天空温度。再接入单隔间动态 GreenLight，先做短窗口数值/因果回归，再做全年多隔间成本与稳定性。开发/试验/独立评测的天气划分及合成扰动必须在正式方法结果前冻结；目前没有冻结，也未运行 LLM 实验。

## 严格读取层与短窗接入

`slowlab/v22/cabauw_weather.py` 现在按已审计的 lc1 v1.0 计划和缓存哈希读取 UTC 月文件，校验 10 分钟 `time_bnds`、标记值、来源索引、重复 SWD 与变量值域；把数据集中误标为 `degC` 的 TA002/TD002 按已核实的 K 数值变换。它保留原始和非负修正后的 SWD，使用露点计算 `vpOut`，用向下长波得到黑体等效 `tSky`。解析器仅返回私有 executor 的时段强迫，不构成可供代理访问的天气工具或传感器。

`ReusableGreenLight` 增加可选天气通道，在首次模型编译前注册 `tOut/vpOut/wind/tSky/iGlob`，随后每个 300 秒步只提交一条当前天气/控制记录；不使用未来行。`results/v22/weather_reader_smoke.json` 记录 49 个月边界读取及 2017-01-01 08:00 UTC 开始的六步烟测：28 个状态保持有限，当前输入行数始终为 1，短波从 2.42 升至 9.06 W/m²。相关现有测试 10 项通过。这仅验证动态输入接线和短窗数值运行；尚未测试全年稳定性、四隔间调度、代理可见事件的端到端因果性或 GreenLight 对真实温室轨迹的一致性。

运行环境需安装 `h5py`（项目提供 `weather` 可选依赖）；缓存位于 Git 外，缺失时不能复现该烟测。GreenLight 的 `co2Out` 和深层土壤温度等边界仍是显式假设，尚未据此作全年物理结论。
