# Phase 1：待机控制、资源积分与清理—重种检查

日期：2026-09-27。**本项动态检查通过；Phase 1 尚未完成，当前暂停在计算规模可行性问题。**

## 合同变化

用户批准共同待机策略。`configs/v22/task_contract_v1.json` 从 v0 派生，记录 v0 哈希；v0 及此前证据不变。v1 新增固定待机控制：10°C 供暖目标（原生平滑带 −1°C）、30°C 通风目标（平滑带 4°C）、关闭补光与 CO₂。这不是刚性温度保证；每 300s 使用最新可用温度，无有效测量则报基础设施错误。清理和空置均使用同一规则，不接受代理修改。

阈值属于开发假设，非实际温室测量或安全认证。供暖 5/10/15°C、通风 25/30/35°C 的敏感性集合已列出，尚未执行。空温室不主动调湿；不声称避免所有结露。

## 实现与验证

- `slowlab/v22/resources.py` 实现共用待机控制器及独立资源账本。按求解器内部时间点梯形积分：送达管路热量、电灯输入、CO₂ 施用、已收获碳流换算鲜重代理、正蒸腾量。面积单位为温室地面 m²；不把供热等同燃料、蒸腾等同灌溉、站立果实等同收获。
- active、cleanup、idle 分账；定植与清理事件单独收费。间隙、重复、非有限与负资源通量被拒绝。停止没有未收获残值收入。
- `scripts/v22/check_standby.py` 使用真实 GreenLight 双模式求解器与 `OnlineObservations` 温度记录。先活作物 300s，停止，完整推进 172800s 清理，再空置 300s，重种后继续 300s。没有跳过物理时钟。
- 模式切换时所有非作物状态保持精确一致；重种冠层温度与平均冠层温度取当前室温。清理未完成的重种请求被拒绝。
- 579 步全部输出有限；空温室作物通量最大绝对值 4.996e-15（浮点辐射残差）；供暖积分对指令×额定功率×持续时间的误差为 0。
- 单线程实测 41.33s。64 项相关轻量测试通过，覆盖新控制、单位换算、重复记账拒绝、失败段不修改账本及既有连续性/观测检查。

动态结果见 `results/v22/phase1_standby_result.json`，含实现与合同哈希。环境是已有固定天气测试夹具，气温范围约 14.17–17.13°C，清理期保护加热几乎不触发；不能据此宣称寒冷天气供暖能力或年度能耗已验证。寒冷/炎热分支有控制器单元测试，没有完整极端天气动态测试。此次记账是已发生费用，不是最终活动结算；最后重种的作物仍在运行。

## 当前问题与暂停边界

按本次含初始化和诊断开销的平均每步 0.07138s 线性外推，四隔间×365天×每天288步需要约 **8.34 单线程小时/campaign**。现有 1024-campaign 草案将对应约 **356 串行天**，且未计离线部署评测。详见 `results/v22/phase1_runtime_projection.json`。这只是数量级警报：既不是全年实测，也不代表未来优化后的耗时；活作物与变天气成本仍不确定。

因此不应直接扩大真实求解规模或通过多进程占满 MacBook。按照用户“完成一个 phase 或遇到问题停下来”的要求，这里暂停。建议下一步先 profile 每步 ODE 求解、全部辅助变量求值与 DataFrame 输出成本，再以原有全状态对照、资源积分误差及独立前缀测试约束优化。不能通过偷偷加大控制间隔、跳过清理天数或减少可观察时点来获取加速。

Phase 1 尚缺多隔间事件调度、完整 active 控制与天气因果接口、权限层、守恒/误差收敛与边界敏感性、整场活动最终结算。未进行 LLM API 调用、大型下载、并行长跑、提交或推送。
