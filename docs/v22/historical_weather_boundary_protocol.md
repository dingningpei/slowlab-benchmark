# Phase 1：真实历史天气边界路线（开发协议）

2026-09-29。v3c 合成天气候选在七个 Cabauw 留年开发折中均未优于真实整年重采样基线，因此不把它冻结为正式站点生成器。当前 GreenLight 活动改以**已归档的真实历史天气序列作为外部强迫**；设施/作物参数才构成模拟 site。历史天气的真实含义限于室外强迫，室内气候、执行器响应、产量和收益仍是模型输出，不是实测温室轨迹。

## 已有数据与用途

- 2017–2020 的 lc1 两产品及 2016-12 初始化边界月已有逐文件哈希、时钟、通道和值域审计；当前私有执行器解析器只接受这些月份。2017 已用于全年运行 pilot，2020 已用于合成天气诊断。因此这四年**都是开发天气**，不能再称为 untouched blind test。
- 2013、2014、2016 的完整年度开发文件已按单独授权下载和审计。旧执行器解析器要求两个产品的重复 SWD 逐行一致；现已新增**独立扩展读取器**，固定气象产品取温度、露点、风速，辐射产品取 SWD/LWD，并保留每月重复 SWD 最大差异。它逐文件检查已批准的 manifest 与完整审计哈希。2014 的 2013-12 初始化月加 365 天、105,121 个 300 秒查询已通过；其中 2014 的 52,560 个十分钟输入与独立构建、哈希锁定的五通道矩阵逐通道比较，最大绝对差为零；见 `results/v22/expanded_weather_2014_boundary_scan.json`。这只证明天气边界可读取，**尚未**跑 2014 年温室动态。2016 全年场景的 2015-12 前月数据尚缺。2012-12 有 89 个 LWD 缺测，不能当作完整天气年。
- 2015/2025 尚未下载或读取。任何新增年度文件获取均须先取得用户对**具体大小和范围**的许可。新年只能在代码、参数分布、指标和排除规则冻结后按预定用途解封；若此前查看过其天气或仿真结果，应改列开发证据。

## 因果与可比性

每个场景选择一个完整、预先审计通过的历史年份。四隔间及所有比较臂共享**同一**天气年和仿真日历；每个条件使用相同的设施/作物 site 参数与随机测量种子。天气年、模型真值参数和未来天气数组仅由独立 executor 持有。代理只经公开 API 得到已到达的室外/室内记录；十分钟归档均值在其区间结束前不得作为可读观测。模型物理积分可读取所需强迫，但这不扩大代理权限。必须用进程边界和出站/返回值测试验证这条规则，不能只靠提示词。

每场采用 365 个本地标准时日，CET=UTC+1，不使用夏令时；2020 闰年取前 365 个本地日，包含 2 月 29 日、排除 12 月 31 日。保留 t=0 所需已结束的前一天十分钟边界记录。不同天气年在统计中是**年份块**，不能把同站点的四个年份、四个隔间或数十万时间点当成独立外部气候样本。任何站点随机效应的复现只支持该 Cabauw 气候条件及明确的模拟参数分布。

## 正式盲测前的硬门槛

1. 继续复核多年度私有天气读取器与完整活动的连续时钟、边界月、闰年和来源索引检查。2014 天气查询扫描和 2017 单年运行 pilot 不能替代跨年完整动态活动。
2. 先冻结设施/作物 site 分布、年度分组、配对单位、主要指标、失败处理与代码哈希，再选择新的独立保留天气年份；不得按仿真收益或策略胜负筛年或筛 site。
3. 公开数据可能被 LLM 预训练见过。隐藏年份身份、精确起始日期、未来强迫和私有 site 参数，且禁止天气预报接口；这只能降低可利用的提前知识，**不能证明模型未记忆公开天气**。应另外做时间/年份身份探测与未来信息泄漏测试。
4. 结果须按天气年份分层报告。若只有少数同站年份，区分对模拟 site 的条件性结论与跨天气年的不确定性，不使用时间点级伪重复来缩小置信区间。

本文件冻结的是从失败合成候选转向真实历史天气的**开发路线与盲测规则**，不是宣布正式天气集合、私有 site 或 Phase 1 已验收。原 `docs/v22/weather_partition_protocol.md` 的 2017–2020 旧划分仍是历史开发记录；其中 2020 保留年身份已因前期诊断失效。
