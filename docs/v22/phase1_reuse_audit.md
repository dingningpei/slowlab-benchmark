## 本轮实现与检查

新增 `slowlab/v22/greenlight_reuse.py` 与 `scripts/v22/compare_reuse.py`。计划将解析结果保留、每步更新控制数据与初始状态，以同条件逐步重载结果作为参照；对比全部 28 个状态，容差 rtol=1e-6、atol=1e-3，并安排指令开关测试。

## 确认的根因

锁定版 `greenlight/_load/core.py` 明确将 JSON/dict 中声明为 input 的变量先放入 aux；只有加载实际输入数据时，才将其注册到 `mdl.inputs`。

本次只添加了 JSON 的 `cmdHeat/cmdVent/cmdCo2/cmdLamp/cmdDay`，加载后 `mdl.inputs` 实际为空；cmdHeat/cmdLamp 的 definition 均仍为 0。加载完成后再给 `input_data` 增加列不会重新生成编译后的依赖关系，控制值没有进入方程。这是我们接入方式的错误，不是 GreenLight 物理模型失效。

首轮曾出现 full_sol 空表缺少 Time 列的普通接口错误，已修复。修复后才暴露并确认上述控制语义问题，不能混淆两次失败。

## 防止误用与后续路径

已加入 `require_dynamic_inputs` 硬检查：加载后必须确认所有命令通道出现在模型 inputs 中，否则在求解前报错。当前复用原型因此被显式阻断，不能生成看似正常的实验结果。此检查不是根因修复。

下一步应在**首次加载/编译之前**通过 GreenLight 支持的输入数据路径注册控制通道，随后仅更新同一组通道的当前值。输入初值可以是合成占位记录，不需要未来天气或任何新数据集。再运行相同 28 状态对照，包含控制切换、端点状态续接和未来输入不干扰；通过后才报告性能优化成功。

按用户“遇到问题停下”要求，本轮停止在根因定位与防误用检查处。未开展整季仿真或 API 实验。当前 Phase 1 仍未完成。

后续每步仅替换同一组动态通道的单行当前输入，保持 300 秒内命令不变。初始状态从上一步末端续接；代码检查所有求解初值与上一状态相等。模型解析只做一次；仍使用官方每步 solve() 路径，不声称已将内部 RHS 函数的所有编译开销消除。
