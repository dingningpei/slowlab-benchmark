# Phase 1：天气—控制器—观察短窗因果检查

日期：2026-09-27。`scripts/v22/check_online_weather.py` 使用已审计的 Cabauw lc1 天气、合同 v2、`ReusableGreenLight`、`OnlineObservations`、共同控制器和 `ResourceLedger`，执行一个 active 隔间的六个 300 秒步。结果在 `results/v22/online_weather_bridge_smoke.json`。该检查 4.44 秒完成，模型只加载一次；不是全年活动或四隔间 executor 验收。

模拟钟 0 对应 2017-01-01 00:00 固定 CET（UTC+1，无夏令时），即 2016-12-31 23:00 UTC。此映射使用已下载的 2016-12 边界月。初始化时刻先创建室内和已结束室外区间的传感器记录，再计算第一次控制。每个 300 秒步由隐藏 executor 使用对应历史天气区间驱动 GreenLight，模拟到端点后才记录室内温湿度与 CO₂；室外温度/太阳短波的十分钟区间均值仅在区间右端点作为观察发布。中间 5 分钟控制更新使用上一条已到达室外记录。

检查了每个控制决策引用的 `measurement_time ≤ available_at ≤ decision_time`；六步所有模型状态有限、每步只有一行当前模型输入，7 条公开室内温度记录和 4 条私有控制器太阳记录符合预期。公开观察存储只含三种室内通道；请求太阳通道被拒绝。资源账本随六个连续区间更新。`requested` 与 `realised` 在此单隔间无共享设施限流的烟测中相同，不能据此宣称已实现容量分配或设备失效。

仍未完成：四隔间共享加热/CO₂/电力约束、停止与重种事件的统一调度、完整公开传感器及 Full/Endpoint 权限、传感器噪声、全年动态稳定性、不同天气年的时间窗和盲测分区。源天气十分钟平均值供隐藏物理模型使用，不在其区间起点作为代理可见测量。该检查没有调用 LLM，也没有验证模拟结果与真实温室轨迹一致。
