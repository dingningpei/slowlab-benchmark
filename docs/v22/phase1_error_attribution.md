# Phase 1：物理故障、来源外推与声明假设的分界

日期：2026-09-29。本协议用于给失败和模型适用范围贴可复核标签，不把任何一种标签自动解释为“已经与真实温室一致”。现有 `configs/v22/component_evidence_v0.json` 的 observed / literature-constrained / assumed / unsupported 是**证据来源**，与以下**问题类型**不同。

| 问题类型 | 判断依据 | 处置 | 当前例子 |
| --- | --- | --- | --- |
| 执行／数值错误 | 相同输入下出现非有限状态、时间断裂、资源账不守恒、编译与参考 RHS 不符或基础设施失败 | 保存失败身份、最小重放、修复后回归；在修复前不删场景也不把它计为代理失败 | 第 240 天原生 RHS 凝结 sigmoid 中间 `exp` 溢出；代数稳定修复有精确状态及 600 步回归。全年固定策略后来通过，但其他情景仍需监测 |
| 来源外推 | 使用了确有出处但**适用对象不同**的方程、设备或外界序列 | 列出源域与目标域差异，做独立条件敏感性；没有匹配真实轨迹时不得声称目标域验证 | GreenLight/AGC 资料到 96 m² 理想隔间；Cabauw 室外天气到拟议温室；简化番茄模型到具体品种 |
| 声明假设 | 没有观测支持的边界、容量、噪声、价格或未建模机制，由合同显式选择 | 冻结数值和范围、报告敏感性或缩小主张；不得以“默认值”冒充测量值 | 深土壤 20°C、中央供应充足、无根区胁迫、零传感器延迟、合成价格 |
| 尚不能归因 | 真实温室轨迹差异或模拟收益异常，但没有足够分解证据 | 同时保留实现、来源和假设三个可能原因；先做可控重放/边界敏感性，随后才尝试归因 | 当前没有匹配真实温室的执行器与室内轨迹，因而不能将任何未知偏差唯一归因 |

一次失败可能跨多个类型。例如深土壤边界下的室温偏移首先是**假设敏感性**；若同输入下参考与编译路径不同，另有**数值错误**。源于 AGC 的设备容量在一个新隔间导致误差属于**来源外推**，不能靠“代码无异常”消除。雾化和 EC 产量响应尚未进入正式核心，属于明确的**不支持范围**，不是零效应结论。

执行顺序：先核对输入/时钟/状态/账本，再用同动作参考路径或精确重放排除实现差异；然后按预先声明的边界和结构参数做配对敏感性；最后才与具有匹配控制输入的真实温室轨迹比较。缺少执行器真值时，这最后一步无法分清控制器/执行器误差与气候/作物方程误差。即使 Phase 1 全年数值与时序通过，论文也只能报告**模拟器内可靠性**和已识别的外部效度限制。
