## 本轮实现

`slowlab/v22/native_rhs.py` 将已校验模型 parser 的数组赋值表达式转成 C。严格 AST 白名单、数组索引边界和赋值目标检查，不接受动态索引或任意函数调用。所有常量按浮点发出，避免整数除法改变方程。

使用本机已有 Apple clang 21，无依赖下载。编译采用 `-O2 -fno-fast-math -ffp-contract=off`，在临时目录生成动态库；临时源代码由模型表达式生成，结果存源码哈希、编译器版本和选项。NaN/Inf、非法运算、除零和溢出使执行失败，不替换成零。下溢未作为致命错误；不声称 C 的告警文字与 NumPy 完全相同。

启用方式：`ReusableGreenLight(..., cached_solver=True, native_rhs=True)`。默认仍为原求解器，生命周期包装器也未自动换后端。未修改上游 GreenLight；LSODA、rtol=1e-6、atol=1e-3、max_step=30s 和 300s 指令/观察频率均保持不变。Python 仍计算全部辅助输出。

## 验证结果

结果与实现哈希见 `results/v22/phase1_native_rhs_result.json`，脚本 `scripts/v22/check_native_rhs.py`。

1. active/empty 各五个导数检查点，室温取 5/10/20/30/35°C、执行器交替开关；预设导数容差 rtol/atol=1e-10，实测最大差 0。它们是有限的诊断状态，不是所有可达状态的证明。
2. 原路径与编译路径各推进 600 步：12 步作物运行，576 步完整清理，再重种后 12 步运行。覆盖昼夜边界，逐步比较原始端点状态及资源账。预设状态容差为原求解器容差，账本 rtol=1e-5、atol=1e-9；实测状态最大差 0，两份资源账本逐值一致。
3. 所有输出有限、空温室碳通量和蒸腾关闭。轨迹模式切换在脚本中显式映射，尚非多隔间生产调度器。参考路径生成相同保持指令，隔离数值内核误差；未声称完整独立传感器闭环已验证。
4. 原路径步进 34.073s，编译路径 2.617s，约 **13.02 倍**；整体测试含四次模型加载、编译、对照和审计约 53.19s。单线程，墙钟上限120秒。
5. 83 项轻量回归测试通过，包括不支持表达式与越界拒绝。未执行大规模活动或 LLM API。

这个加速是同一固定天气夹具的配对步进测量，多数步为空温室；不是全年性能预测，不保证其他平台逐位一致。全季节精度、作物成熟过程、变化天气、边界敏感性和数值收敛还没有验证。

## 当前暂停点：保温幕未接入共同控制时序

`results/v22/phase1_screen_control_audit.json` 校验锁定扩展文件哈希后确认：`uThScr=min(thScrCold,thScrHeat,thScrRh)`，其中 `thScrHeat` 读取内部 tAir，`thScrRh` 读取内部 rhIn/ventCold；它们在 RHS 中随求解器评估。外部保持指令只有供热、通风、CO₂、补光，没有保温幕。

这与合同“只使用最新可用传感器、保持指令至下个300s tick”的共同底层控制时序不一致。不是发现未来天气泄漏，也不是 native 模型本身的错误；是集成合同尚未落实。原生幕布又依赖原生 heatSetPoint/rhMax，需明确与新处理或待机设置的关系。

单步诊断中 uThScr 固定在约1e-22，冷侧最小值遮蔽了其他反馈变化；thScrRh 在步内变化约0.0001505。最初断言幕布必须有运动的探测未成立，已移除该错误假定。审计结论依据源码依赖和未注册通道，不把当前夹具的零运动说成结果偏差。

建议下一步：保留原生幕布响应曲线，将其移到公共底层控制器，读取已到达的室内温度/RH、室外温度和时钟；明确 active/standby 的共同目标，注册 `cmdScreen` 并保持到下个tick。随后补依赖审计、无未来/未到达观测测试，以及缓存/编译路径与生命周期回归。幕布仍是共同设施控制，不增加代理决策维度。

按用户“遇到问题停下来”的要求，这里暂停。不能宣布 Phase 1 完成。多隔间事件调度、天气接口、权限链、守恒与最终结算等清单仍待完成。
