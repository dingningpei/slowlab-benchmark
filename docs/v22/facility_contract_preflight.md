## 发现的结构问题

锁定 GreenLight 源码中：

- `hCovEOut = sensible(aCov / aFlr * (cHecOut1 + cHecOut2 * wind**cHecOut3), tCovE, tOut)`；围护结构通过一个集中表面与室外换热。
- `hTopCovIn` 使用同一 `aCov/aFlr`；空气热容量由 `hAir` 与 `hGh-hAir` 定义。
- 所选官方组合没有独立的走廊/邻室温度状态或逐墙换热输入。这里的结论仅限所选文件，不声称 GreenLight 平台无法扩展。

已有 WUR 设施资料显示隔间具有外墙、邻室与走廊边界。把全部墙面算作室外暴露面会改变热损失；直接删去共享墙面积则隐含忽略它们的换热。两种做法都不能冒充同一个真实隔间。

这比“缺少一个设备参数”更基础：**必须先确定实验单元的热边界模型，才能冻结有效围护面积和容量合同。** 仅缩放面积或拟合一个散热系数无法建立逐边界的物理解释。

## 建议解决路径，尚未实施

优先保留研究隔间定义，为模型设计外部围护与邻室/走廊两类明确的换热路径。邻室/走廊可先使用固定的、预注册的外生边界温度场景；缺少实测值时标明是模拟假设，并在开发阶段检查敏感性。此时实验处理之间无直接热串扰属于模型假设，不能声称复现真实共享温室。

需要确定换热接到哪一空气层、墙面面积/传热系数/热容量、各边界温度来源，以及是否考虑水汽/空气渗漏。不能将墙面热流简单加入后仍重复计入原来的 `aCov`，也不能把新墙面作为同等光照透射面积而不检查光学路径。

另一条路径是独立外露的 96 m² 模拟温室，但它改变了设施拓扑，不应在未经明确决策的情况下替换当前隔间目标。
