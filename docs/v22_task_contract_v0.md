# SlowLab V2.2：Phase 0 任务合同 v0

日期：2026-09-27。**Phase 0 合同交付完成；Phase 1 尚未开始。**

权威机器可读合同：`configs/v22_task_contract_v0.json`。该版本冻结供实现使用的开发定义，不是正式实验预注册，更不是通过真实轨迹验证的声明。此前审计文档是决定的历史；与本合同冲突的历史候选不再作为实施要求。

## 1. 研究对象与模型口径

研究 LLM 在有限温室资源下安排实验、随时读取已产生证据、停止或启动下一项实验，最后推荐管理策略的能力。

一个物理处理单元是 96 m² 独立控制的模拟隔间。每场活动有 4 个隔间，所有方法使用相同面积和容量。统计独立单位仍是 site；植物、隔间、时间点不是新的独立 site。

采用已锁定的 GreenLight Vanthoor 气候＋简化番茄＋Katzin 顶部 LED 组合。保留集中辐射，加入用户同意的有效显热边界修正。不是 AGC 设施复现，不使用矮生番茄产量去校准这个作物族。

面积口径统一为 greenhouse floor area。原生 crop pools、LAI 和产量均按其每平方米地面定义使用，不额外乘 AGC 净种植面积比例，不把连续冠层换算成独立植株重复。因此既有 76.8/62.5 m² 冲突不作为本模板的隐含换算系数。

根区固定充分供水供肥；不开放灌溉/EC。幕布采用共同固定的原生保温幕规则；不增加遮光幕、株间灯、雾化、机械制冷或生长管。没有模拟的过程不能写成已验证能力。

## 3. 六维管理方案与因果执行

| 字段 | 范围 | 含义 |
| --- | --- | --- |
| day_temperature_c | 18–26°C | 日间供暖目标 |
| night_temperature_c | 15–22°C，且不高于日间 | 夜间供暖目标 |
| co2_target_ppm | 400–1200 ppm | 光照活跃时的施用目标 |
| supplemental_light_hours | 0–16 h/day | 从 06:00 起的允许补光窗口 |
| vent_temperature_offset_c | 2–6°C | 相对供暖目标的通风温度偏移 |
| vent_rh_threshold_pct | 70–90% RH | 湿度通风触发值，非 VPD |

范围是开发域，不是“最佳农业参数”。策略启动后不可修改；代理可停止作物、清理后换策略重种。

固定当地标准时钟、无夏令时。日间定义 06:00–22:00，控制每 300 秒更新。灯具仅在允许窗口、最近可用太阳辐射低于 400 W/m²、最近可用室温低于 35°C 时开启。CO₂ 仅在最近可用自然光超过 20 W/m² 或灯具开启时按原生比例控制。

禁止使用未来全天实际 dayRadSum；也不把“截至当前累计值”静默塞进预测全天的字段。原生 lampNoCons/smoothLamp/isDay 系列涉及的依赖必须在 Phase 1 一并替换。控制器看到的测量按 tick 保持，不直接读取未来端点。目标值与实际温度、浓度、设备功率分别记录。

## 4. 时间、预算与观测

- 活动窗口 365 天，单个正常作物运行 180 天，清理 2 天，最晚新启动日 183。以上是基准资源假设。
- 最多 16 次启动、32 次决策调用、128 次工具调用，最大上下文 32768 tokens；这些不构成付费 API 执行授权。
- 容量、面积和日历构成物理上限；不另设隐藏的货币阈值。能源与费用逐项报告。
- 传感器每 300 秒记录一次，v0 延迟为 0、无随机测量噪声。它是理想化虚拟传感器版本，不声称复现真实噪声；时间接口已支持未来另行声明的延迟/噪声。
- LLM 可在任意当前时刻读取过去记录，不必等 round/loop 结束。读取不推进物理时间；推进必须显式请求。尚未采样的时刻返回最近已到达记录及原时间，不凭空插值。
- Full 可见过程信息；Endpoint 在运行中只见操作确认与粗粒度安全事件，正常结束后见最终汇总。提前停止只释放当时已收获量、已消耗资源与删失标记，不释放隐藏过程或完整周期反事实。

## 5. 收获、贡献毛利与失败处理

原生 `mcFruitHar` 按时间积分得到收获 CH₂O 质量。沿用官方 `scripts/greenlight_example.py` 的约定，乘 1e-6 后除以假定干物质比例 0.06，得到 **鲜重等价量** kg/m²；这是模型换算，不含成熟度、品质分级或商品率预测。站立果实 `cFruit` 不算累计收获。

v0 价格/成本均为固定合成情景：果实 2 EUR/kg、采收费 0.05 EUR/kg、电 0.15 EUR/kWh、送达管路的热量 0.05 EUR/kWh、CO₂ 0.2 EUR/kg、定植 2 EUR/m²、清理 0.5 EUR/m²、背景服务 0.01 EUR/m²/活跃日。不是当前市场报价。

主要指标是最终推荐在独立 180 天部署中的**模拟贡献毛利 EUR/m²**：收入减以上变动成本；不含设施资本成本和租金。热量积分使用送入管路的热流，不能混称燃料输入；水只另报正蒸腾积分，不把它当实测灌溉。既报鲜重等价量，也报原生收获、热、电与 CO₂ 消耗；干物质比例 0.05/0.06/0.07 的敏感性检查保留。

活动中提前停止仍结算已发生费用、已收获量及清理费，未收获作物残值为零。清理占用资源；截止时未完成作物删失，不伪造未来收获。空置期设施状态仍连续，待机能耗在活动层记账，不能静默抹去。

连续 1 小时室温低于 5°C 或高于 40°C 触发安全停止。这是基准保护规则，不是已验证死亡模型。数值求解失败属于基础设施问题，保留身份并暂停，不能记为代理差表现或偷偷删 site。

最终推荐无效/缺失时使用事先冻结的有效初始推荐并标记 fallback。离线评测使用独立、各方法共用的天气重复，数量在 Phase 3 按精度冻结；评测不向代理反馈。完整活动花费与最终推荐质量分开报告。

## 6. 最小数据字典

| 层 | 必备字段/单位 | 权限 |
| --- | --- | --- |
| 实验身份 | campaign_id、unit_id、run_id、policy_hash、协议版本 | 公共身份；不能编码私有 seed |
| Design | 提交时间、六维策略、start/stop/recommend、拒绝原因 | 当前可见操作 |
| Executor | requested_policy、控制时间、设备指令与实际状态、成本流量单位 | 完整私有审计；代理只见权限内字段 |
| 传感器 | compartment、variable、unit、measurement_time、available_at、value | 新 `OnlineObservations`；时间均为模拟秒 |
| 气候观测 | 温度 °C、RH %、CO₂ ppm | Full 过程可见；Endpoint 等待终点 |
| 作物观测 | canopy_lai_proxy、已收获鲜重等价量 kg/m² | 虚拟传感器，不开放私有碳库 |
| 资源 | 热/电 kWh/m²、CO₂ kg/m²、面积×天、种植/清理事件 | 权限内发布；私有审计完整记录 |
| 终止 | normal/early/safety/deadline、时间、删失、已结算成本与残值 | 不含未发生的收获 |
| Reader | 查询范围、所获记录身份、工具与最终推荐 | 不能读未来或 evaluator 输出 |
| Evaluator | 独立评测身份、质量、资源、失败类型 | 私有，不进 LLM payload |

完整新执行器中的派生观测与实际日志仍需 Phase 1 实现。逻辑示例不是伪造 Design/Executor/Reader 实验数据。

## 7. 可执行合同验收与下一阶段

`python3 scripts/verify_v22_task_contract.py` 检查几何/容量单位并执行 `configs/v22_campaign_example_v0.json` 的调度演练：两个隔间启动，第 14 天观察并停止一个，第 16 天重种，另一个正常完成后再次启动，最后在第 365 天推荐。

预期：4 次启动、1 次早停、3 次正常完成，活跃隔间天数 554、清理隔间天数 8，占用 53952 m²·day。按合同确定的定植/清理/背景服务费用为 1491.84 合成 EUR；没有模拟能源或收获，因此不输出完整实验成本或毛利。

本轮 39 项相关测试通过，覆盖调度/清理占用、未来查询、参数范围、单位关系和此前观测接口。未执行 GreenLight 长周期仿真或 LLM API。

**Phase 0 的完成仅指任务合同、数据字典与可执行逻辑示例完成。** Phase 1 必须检验：控制响应、热边界近似、可收获性、闲置与重种状态连续性、成本积分、无未来信息泄漏、数值稳定及单机负载。发现失败应升版并记录原因，在正式 sites 生成前重新冻结；不能把本次文档/单测验收称为这些动态验证通过。
