# Phase 1：求解性能定位与缓存回归

2026-09-27。状态：**等价缓存优化通过，但计算规模门槛仍未解决，Phase 1 暂停。**

## 测量和实现

先在锁定 GreenLight 源码与已有 runtime 下，用单线程 profile 12 个活作物物理步。初始化不在计时内。结果保存在 `configs/v22_phase1_solver_profile.json`；可用 `scripts/profile_v22_solver.py` 复现。高层累计计时约为：step 0.762s，ODE 求解 0.513s，全部输出计算 0.160s。cProfile 有开销，动态生成函数的源码标识会重叠，因此不据单个生成函数行作精确分摊。

`slowlab/v22_cached_solver.py` 缓存原生 parser 已生成的 RHS 和辅助表达式编译结果，移除每次 RHS 的进度输出。保留全部方程、求值顺序、所有辅助输出、LSODA、原容差和 max_step=30s；控制和观测仍为 300s。运行时异常与非有限输出不能静默转零。模型表达式或求解配置改变则拒绝复用；仅支持当前锁定的 numpy/left-input/LSODA 配置。

`ReusableGreenLight(..., cached_solver=True)` 显式启用；**默认仍为参考路径**。没有修改上游 GreenLight 源码，没有引入数值编译器依赖。当前缓存只接单隔间适配器，生命周期包装器仍使用参考路径，不能将此结果误认为整场活动已提速。

## 回归证据

`configs/v22_phase1_cached_solver_result.json`：active、empty 各 12 个 300s 步，跨越 22:00 控制日界并改变热、光、CO₂ 和通风指令。同一个测试步依次比较原求解器和缓存求解器，未随机化计时顺序，故速度值只作开发诊断。

- 求解时间网格和 DataFrame 形状相同。
- 所有状态、所有辅助输出逐值一致，最大绝对差 0。
- 每步累计资源账本逐值一致。
- 参考路径总计 1.7784s，缓存路径 1.4548s，约 **1.222 倍**。
- 71 项相关轻量测试通过，包括不支持配置拒绝、表达式变化检测及原有资源/生命周期/观测检查。

这些是固定天气短测，不是全年误差收敛或未来天气因果验证。原两天清理检查仍是参考路径证据，未声称已在缓存路径重跑。

## 当前暂停原因

这次缓存改动有效，但幅度不足。按本次不同短测的平均缓存步耗时线性外推，四隔间全年仍约 7.08 小时/campaign；这不是新的全年实测，也不能和上一轮包含初始化的 8.34h 直接算提速百分比。

主要瓶颈仍为微分方程重复求值。继续扩大矩阵或简单增加 MacBook 并行度不合适。下一步应独立开发并审计编译型数值内核或等价 RHS 加速：先确认编译工具链和依赖，再逐导数、跨模式、极端边界、多日轨迹与资源积分对照，最后重新评估运行预算。不能通过放宽精度、拉长控制间隔或跳过空置物理时间绕过门槛。

当前运行环境未发现 Numba、JAX 或 Cython；本轮没有安装，也没有把“未安装依赖”当作科学失败。需要解决的是保持数值可信度的实质加速路径。按照用户遇到问题暂停的要求，本轮停在此处；未启动大规模计算或 LLM API。

多隔间调度、完整天气/控制器/权限因果链、守恒和灵敏度检查、最终结算仍未完成。Phase 1 不能打勾。
